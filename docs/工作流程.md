# 开发工作流程

## 分支策略

```
main ─────────●────────●────────●───
              │        │        │
platform ─────┘        │        │
enterprise ────────────┘        │
workflow ───────────────────────┘
```

- `main` — 稳定分支，所有功能最终合并到这里
- `platform` / `enterprise` / `workflow` — 功能分支，独立开发

## 日常开发流程

### 1. 创建 worktree（首次）

```bash
# 在项目根目录执行
git worktree add -b <分支名> ../AnyDeals-<分支名> main
```

### 2. 进入 worktree 开发

```bash
cd ../AnyDeals-<分支名>
# 开发、测试、提交...
git add .
git commit -m "feat: xxx"
```

### 3. 合并回 main

```bash
cd ../AnyDeals-Hermes    # 回到主仓库
git checkout main
git merge <分支名>
git push origin main
```

### 4. 清理 worktree

```bash
git worktree remove ../AnyDeals-<分支名>
git branch -d <分支名>
```

## 上游同步流程

从 [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent) 拉取更新。

### 自动同步

```bash
./sync-upstream.sh
```

脚本执行步骤：
1. `git fetch upstream` — 拉取官方最新代码
2. `git checkout main` — 切换到主分支
3. `git merge upstream/main` — 合并官方更新
4. `python rebrand.py` — 重新应用品牌变更
5. `git push origin main` — 推送

### 手动同步

```bash
git fetch upstream
git merge upstream/main

# 如有冲突，手动解决后运行：
python rebrand.py
```

### 冲突处理原则

1. 保留我们的品牌修改（`~/.anydeals`、`AnyDeals` 名称）
2. 保留上游的新功能代码
3. 不要丢弃上游变更 — 合并双方代码

## 品牌检查

合并或修改后，检查是否有遗漏的 `hermes` 引用：

```bash
python rebrand.py --check
```

输出 `✓ 没有遗漏` 即为通过。

## 测试

```bash
# 激活虚拟环境
source .venv/bin/activate

# 运行全部测试（跳过集成测试）
python -m pytest -q -m "not integration" -n auto

# 运行品牌相关测试
python -m pytest -q tests/AnyDeals_cli/test_completion.py tests/AnyDeals_cli/test_profiles.py tests/test_AnyDeals_*.py
```

## 常用命令速查

| 操作 | 命令 |
|------|------|
| 查看所有 worktree | `git worktree list` |
| 创建新功能分支 | `git worktree add -b <名称> ../AnyDeals-<名称> main` |
| 删除 worktree | `git worktree remove ../AnyDeals-<名称>` |
| 删除分支 | `git branch -d <名称>` |
| 品牌检查 | `python rebrand.py --check` |
| 品牌重塑（预览） | `python rebrand.py --dry-run` |
| 品牌重塑（执行） | `python rebrand.py` |
| 上游同步 | `./sync-upstream.sh` |
